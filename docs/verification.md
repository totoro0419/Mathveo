## レスポンシブ表示

同じ実装を独立したiframeビューポートで操作しました。設定幅にはデスクトップChromeの縦スクロールバー15pxが含まれます。

| 設定幅 | 実際の本文幅 | 確認画面                           | ページの横はみ出し |
| ------ | ------------ | ---------------------------------- | ------------------ |
| 390px  | 375px        | ホーム・ライブラリ・動画視聴・教材 | なし               |
| 820px  | 805px        | 同4画面                            | なし               |
| 1440px | 1425px       | 同4画面                            | なし               |
| 320px  | 305px        | 同4画面                            | 修正後はなし       |

320pxで科目ナビの負の余白とbodyの最小幅によるはみ出しを修正しました。390pxでルートの文字サイズを200%にする確認も行い、4画面のDOM測定で本文幅を超えるページ幅は生じませんでした。数式・タブ・科目の局所スクロールは許容する構造です。

PCは動画と教材を横に並べます。タブレットの縦持ち相当ではナビをアイコンのレールに変え、視聴を縦並びにします。スマートフォンは4項目の下部ナビを使い、動画、情報、教材、学習記録の順で読み進めます。画面の確認はAndroid実機やタッチジェスチャーの試験とは別です。

## 動画：実装と確認の境界

公式IFrame Player APIの読み込みと、指定動画IDの公式プレーヤーの表示を確認しました。プレーヤーにタイトル・投稿者・操作ボタン・約2分58秒の再生時間が表示されました。

再生ボタンを操作しても、この検証環境では動画本体が読み込まれず、HTML videoの再生位置0秒・readyState 0のまま進みませんでした。原因を動画側の埋め込み禁止やbot対策とは断定していません。**実映像・音声の再生、途中位置での保存と再開、最後までの再生は未確認です。**

再生位置の2秒ごとの保存、停止時・画面離脱時の保存、再開時のseek、終了と理解度の分離は実装済みです。通常のインターネット接続のブラウザとAndroid実機での再確認が必要です。プレーヤーの制限を回避する仕組みは実装していません。

YouTubeの画像ホストからは画像の代わりに「Site Unavailable」のHTMLが返り、この環境ではサムネイルを表示できませんでした。UIのテーマ図はMathveo独自のフォールバックであり、取得した動画サムネイルの実物ではありません。
