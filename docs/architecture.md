# 実装構造と引き継ぎ

## M01の構成

Next.jsやPostgreSQLを先行導入せず、React 19 / TypeScript / Viteの静的アプリとして実装しました。認証サーバーを要しないM01の教材・画面遷移・端末保存に必要な構成です。APIキーはUIから完全に分離しています。

学校段階→科目→単元→テーマ→動画の関係を画面とデータに分離しました。現在の独自教材は高校／数学Ⅰ／二次関数のみです。中学・旧課程・入試・Shorts・ライブを含む網羅的な分類は未完了です。

教材は動画IDをキーにしません。`VideoTopicLink`は`direct / related / candidate`と根拠を持ちます。元の科目と現科目は別のフィールドに保持します。確認済み教材と未検証教材は`validation`で分けられます。

## 保存の意味

`topic:テーマID`は学習状態・理解度・復習・メモ・確認問題、`video:VideoID`は再生位置・プレーヤーから得た長さ・再生完了を保存します。YouTubeの公的メタデータの長さと、利用者のプレーヤー記録を混同しません。

保存完了はIndexedDBのトランザクション完了後に表示します。保存失敗時はローカルの入力を保持し、再試行とJSON書き出しを提示します。別タブでメモが変更されたときは無条件に上書きしません。クラウド同期・競合の統合UI・書き出しファイルの復元は今後の課題です。

## M02以降

2026-10-12に、公式サイトの高校数学33・中学数学12、計45再生リストのアプリ内視聴を追加しました。`PlaylistStudy.tsx`は標準のYouTube iframeを表示し、科目内ナビ・検索・現行／元の分類をつなぎます。既存の`YouTubePlayer.tsx`・IndexedDB保存処理は変更していません。再生リスト内の個別動画情報、再生位置・理解度・メモなどの記録は、Data API収録後にVideo ID単位で接続する課題です。

全件収録では一つのチャンネルだけを対象にしないでください。公式サイト掲載の数学Ⅱ・B、数学Ⅲのプレーヤーには別の投稿チャンネルが表示されます。詳細は[収録基盤の資料](youtube-sync.md)に追記しました。
